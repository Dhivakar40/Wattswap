# Settlement

How a WattSwap trade is authorized, priced and settled on-chain.

> Testnet/demo scope: the energy token is backed by *simulated* meter readings and payment is a
> mock stablecoin (mUSDC). Nothing here implies physical energy delivery or real-money settlement.

## Units

| Quantity | Unit | On-chain type |
|---|---|---|
| Energy | WATT base unit = **1 Wh** (`decimals = 3`, so 1.000 WATT = 1 kWh) | `uint256 amountWh` |
| Payment | mUSDC, 6 decimals | `uint256` |
| Price | mUSDC base units **per kWh** (6 dp), e.g. `150000` = 0.150000 mUSDC/kWh | `uint256 limitPrice / execPrice` |
| Fee | basis points of cost | `feeBps` (max 500 = 5%) |

```
cost            = floor(fillWh * execPrice / 1000)        # Wh -> kWh
fee             = floor(cost * feeBps / 10000)
seller receives = cost - fee
treasury        = fee
buyer pays      = cost
```

Worked example: 10 kWh (`10000` Wh) at `150000` with `feeBps = 100`:
`cost = 10000 * 150000 / 1000 = 1_500_000` (1.5 mUSDC), `fee = 15_000` (0.015), seller gets `1_485_000`.

Rounding is always *down*. A fill whose `cost` rounds to 0 reverts with `DustFill`, so energy can never
move for free. For non-dust fills the rounding error is < 1 micro-mUSDC.

## EIP-712 domains

| Contract | `name` | `version` | `chainId` | `verifyingContract` |
|---|---|---|---|---|
| WattSwapExchange (orders, quotes) | `WattSwapExchange` | `1` | chain id | exchange address |
| EnergyToken (meter readings) | `WattSwap Energy` | `1` | chain id | token address |

The domain separator is the replay boundary across chains and deployments.

## Typed structs

### Order (signed by the maker's wallet; EOA or EIP-1271 contract wallet)

```
Order(address maker,bytes32 marketId,uint8 side,uint256 amountWh,uint256 limitPrice,
      uint256 expiry,uint256 nonce,bytes32 salt)
```

| Field | Meaning |
|---|---|
| `maker` | Signer and the account that is debited/credited. |
| `marketId` | `keccak256("WATT-mUSDC")` in v1. Part of the signed type from day one so adding markets needs no breaking change. `settle` requires `buy.marketId == sell.marketId` and the market to be enabled. |
| `side` | `0` = buy, `1` = sell. |
| `amountWh` | Total size in Wh. May be filled in several partial fills. |
| `limitPrice` | Buy: maximum acceptable price. Sell: minimum acceptable price. mUSDC/kWh, 6 dp. |
| `expiry` | Unix seconds. Valid while `block.timestamp <= expiry`. |
| `nonce` | Used by `cancelUpTo`: orders with `nonce < minNonce[maker]` are void. |
| `salt` | Makes otherwise identical orders distinct (distinct order hashes). |

The order identity is its EIP-712 digest (`hashOrder`). On-chain state per order: `filled[hash]`,
`cancelled[hash]`; per maker: `minNonce[maker]` (ADR-002).

### PriceQuote (signed by an account holding `PRICER_ROLE` on the PriceOracle)

```
PriceQuote(bytes32 marketId,uint256 price,uint256 timestamp)
```

The pricing engine's reference price at `timestamp`. Quotes are not single-use: they are valid for as long as
they are fresh (`block.timestamp - timestamp <= PriceOracle.maxStaleness()`), because several fills may be
settled against the same reference price.

### Reading (signed by the meter's device key; verified by `EnergyToken.mint`)

```
Reading(bytes32 meterId,bytes32 readingId,uint256 amountWh,uint256 intervalStart,uint256 intervalSeconds)
```

Test vectors for all four signed messages (buy order, sell order, quote, reading) live in
`packages/shared/vectors/eip712.json`, generated by `contracts/test/Vectors.t.sol` and verified in CI by both
Foundry and viem. Python code (Phase 4) must reproduce the exact same digests and signatures.

## `settle()`

```solidity
settle(Order buy, bytes buySig, Order sell, bytes sellSig,
       uint256 fillAmountWh, uint256 execPrice, PriceQuote quote, bytes quoteSig)
```

Only `RELAYER_ROLE`; not paused; non-reentrant. Checks, in order (each failure is a distinct custom error):

1. `buy.side == BUY`, `sell.side == SELL` (`InvalidSide`)
2. same `marketId` (`MarketMismatch`), market enabled (`MarketDisabled`)
3. `buy.maker != sell.maker` (`SelfTrade`), `fill > 0` (`ZeroFill`)
4. `sell.limitPrice <= execPrice <= buy.limitPrice` (`PriceOutOfLimits`)
5. for each order: not expired (`OrderExpired`), not cancelled (`OrderIsCancelled`),
   `nonce >= minNonce[maker]` (`NonceTooLow`), valid signature via `SignatureChecker` (`InvalidOrderSignature`),
   `fill <= amountWh - filled` (`Overfill`)
6. quote: same market (`QuoteMarketMismatch`), not from the future (`QuoteFromFuture`), fresh (`StaleQuote`),
   signer holds `PRICER_ROLE` (`InvalidQuoteSigner`), and
   `|execPrice - quote.price| * 10000 <= quote.price * bandBps` (`PriceOutsideBand`)
7. `cost > 0` (`DustFill`)

Then effects (`filled[buyHash] += fill`, `filled[sellHash] += fill`) and three `SafeERC20.safeTransferFrom` calls:
WATT seller→buyer, mUSDC buyer→seller (`cost - fee`), mUSDC buyer→treasury (`fee`, skipped if 0). Finally
`TradeSettled(marketId, buyHash, sellHash, buyer, seller, fillWh, execPrice, cost, fee)`.

`bandBps` is admin-settable (`setBand`, ≤ 2000, emits `BandUpdated(old, new)`).

## Why `settle()` is atomic

1. **One transaction.** Both legs of the trade (energy and payment) are executed inside a single call frame.
   The EVM guarantees that a transaction either commits all of its state changes or none: if any statement
   reverts, every storage write and every token transfer made earlier in the same transaction is rolled back.
2. **No partial path.** There is no `try/catch` and no low-level call whose failure is swallowed.
   `SafeERC20.safeTransferFrom` reverts on a failed or false-returning transfer, so a seller without enough
   WATT, or a buyer without enough mUSDC/allowance, aborts the whole trade, including the fill accounting.
   This is tested for the case where the payment leg fails *after* the WATT leg already ran, and for a failure of
   the final fee leg (`test_revert_insufficientAllowanceOrBalance_isFullyAtomic`,
   `test_revert_feeLegFailure_rollsBackEverything`).
3. **Custody-free.** The exchange never holds tokens: transfers go directly maker→maker/treasury using the
   makers' approvals. There is no intermediate state in which funds sit in the contract, which an invariant test
   checks (`balanceOf(exchange) == 0` for both tokens after arbitrary sequences of actions).
4. **Checks-effects-interactions + reentrancy guard.** Fill accounting is written before any external call, and
   `nonReentrant` blocks re-entry through token hooks, so a reentrant call cannot observe or exploit
   half-updated state.
5. **Signed authorization.** Neither the relayer nor anyone else can move funds that a maker did not authorize: each
   debit is bound to a signed order (amount, price limit, expiry, market) and to a signed fresh price quote.

Consequence for the off-chain system: a settlement either confirms with both legs, or reverts with a precise
custom error and nothing moved. The backend (Phase 4) maps a revert to `failed` and releases the orders.

## Cancellation

- `cancel(order)`: maker only; marks that order hash cancelled (`OrderCancelled`). **Binding.**
- `cancelUpTo(n)`: maker only; strictly increasing; voids every order with `nonce < n` (`NonceFloorRaised`). **Binding.**
- `DELETE /api/v1/orders/{hash}`: removes the order from *our* book (`cancel_type: "offchain"`). Not binding:
  the signature stays valid on-chain, which is safe only while `settle()` is relayer-gated (ADR-004 addendum).
  With Wh already reserved by in-flight settlements it cancels only the unreserved remainder and marks the order
  `cancel_pending`; the order is finalized as cancelled when those settlements resolve.

Orders cancelled on-chain are reported as `cancel_type: "onchain"`; the UI can label them "Cancelled on-chain" and
offer "Cancel on-chain (costs gas)" using the ABI fragments in `GET /markets/{id}/order-config`.

## Off-chain order flow (Phase 4)

```
POST /orders -> verify (EIP-712 digest == exchange.hashOrder, OZ-equivalent signature rules, bounds)
             -> funding check (balance AND allowance cover ALL the maker's open orders, one pinned block)
             -> orders table
matcher   (price-time priority; skips self-trade; price = clamp(reference, limits ∩ quote band))
   -> trade + settlement(matched), Wh reserved on both orders
relayer   (pre-flight: expiry, voided/unfunded -> cancel; FRESH quote; re-derive price)
   -> settlement(submitted): raw signed tx persisted BEFORE broadcast; replaced at the same
      nonce (fee bump + fresh quote) when stuck
listener  (TradeSettled at depth N, idempotent by (txHash, logIndex), reorg rollback)
   -> settlement(confirmed): filled_wh += fill, reserved_wh -= fill
```

Settlement states: `matched -> submitted -> confirmed | failed`. A failed settlement releases the reservation on
both orders with a recorded reason; an order that caused the failure is removed with a `cancel_reason`
(`on_chain_cancel`, `nonce_floor`, `unfunded:balance`, `unfunded:allowance`). Pairs released because no price fits
go on an exponentially growing cooldown (default 30 s, doubling, capped at 600 s).

### Minimum sizes

Orders below `MIN_ORDER_WH` (100 Wh) are rejected. A fill must cost at least `MIN_FILL_COST` mUSDC base units
(contract math: `fill * price // 1000`), so a `DustFill` revert never burns relayer gas. A leftover below
`MIN_FILL_WH` after a partial fill is closed with `cancel_reason = "dust_remainder"` (shown to users as
"Filled — remainder below minimum closed").

### Signature rules

Exactly 65 bytes, `v` in {27, 28}, low `s` (OpenZeppelin rejects high-s), recovered signer equals `maker`. EIP-2098
64-byte compact signatures are valid on-chain but rejected by the API in v1. Makers with contract code are
verified through ERC-1271 `isValidSignature`. Python reproduces every Foundry-generated vector byte for byte
(`tests/unit/test_order_vectors.py`, CI-gated).

## Approvals the user must grant

- Sellers: `WATT.approve(exchange, amount)` (or `permit`, since WATT is ERC20Permit).
- Buyers: `mUSDC.approve(exchange, amount)`. The UI must explain that this lets the *exchange contract* pull
  payment only when a trade matching their signed order settles.
