# Phase 3 — Pricing engine

Branch: `phase-3-pricing` · Target tag: `v0.3.0` (after approval)

Status: **IMPLEMENTED — awaiting PR approval.** Items marked **DECISION** were proposed defaults; the owner's changes are recorded under *Owner changes*.

## Starting state (facts that shape the design)

- Phases 0–2 merged and tagged `v0.2.0`. The API has Redis, Postgres, a leader-locked background-worker pattern (mint worker), a `TxSender` (nonce lock, fees, receipts), admin gating (`AdminDep`, `ADMIN_ADDRESSES`) and the shared EIP-712 vectors.
- `price_ticks` exists as a schema-only table (columns `supply_wh`/`demand_wh` are misnamed for what this phase needs; it is empty, so a migration may reshape it).
- **`PriceOracle` (Phase 1) stores exactly one price**: `updatePrice(uint128 price, uint64 timestamp)`, `PRICER_ROLE` only, `timestamp` strictly increasing and `<= block.timestamp`, `maxStaleness` default 5 min. It does **not** verify signatures.
- **Quotes are verified by `WattSwapExchange._checkQuote`**, not by the oracle: `quote.marketId == order.marketId`, `quote.timestamp <= block.timestamp`, `block.timestamp - quote.timestamp <= oracle.maxStaleness()`, signer holds `PRICER_ROLE` **on the oracle**, and `|execPrice - quote.price| <= bandBps` (admin-set on-chain). The exchange never compares the quote to `oracle.latest()`.
- `price_quote` already exists in `packages/shared/vectors/eip712.json` (Phase 1, generated by Foundry). Units: price = mUSDC base units (6 dp) per kWh; energy = Wh (WATT, 3 dp); `cost = floor(fillWh × price / 1000)`.

## Scope

In: pure deterministic pricing core, per-market regions and per-cell weather, Open-Meteo provider, volatility controls and circuit breaker, ticker + weather poller + oracle pusher workers (leader-locked), persistence, signed `PriceQuote`s, Redis publishing, admin config endpoints, read endpoints for price/ticks/forecast, backtest CLI, docs, tests, CI.
Out: order book, matcher, relayer, chain listener (Phase 4); WebSocket gateway (Phase 5); UI (Phase 6). Demand reads open bids and fills through a repository that returns 0 until Phase 4 fills the tables.

## Architecture

```
                    pure, no I/O (Decimal/int only)
        ┌───────────────────────────────────────────────┐
inputs ─►  model.py  supply / demand / raw price         │
(weather,│ smoothing.py EMA, rate limiter, clamp          │──► Tick (ints for chain, Decimals for analytics)
 meters, │ breaker.py   state machine                     │
 orders, │ volatility.py rolling realized vol             │
 clock)  │ engine.py    step(state, inputs, params) → (state', tick)
        └───────────────────────────────────────────────┘
edges:  weather.py (httpx, respx-testable)   repo.py (SQLAlchemy)   quotes.py (EIP-712)   publish.py (Redis)
        service.py: leader-locked ticker, weather poller, oracle pusher     routers: markets, admin
```

Everything priced, signed or sent on-chain is an `int` (mUSDC micro-units per kWh) produced by quantizing a `Decimal` computation. Floats exist only at the JSON edge of Open-Meteo parsing and are converted with `Decimal(str(x))` immediately; no float reaches the model, a signature or a transaction. A test asserts that the engine, quote and oracle paths never see a `float`.

## Markets, regions and weather (per region, not per meter)

- **Grid cell**: `cell = (floor(lat_e6 / 500_000), floor(lon_e6 / 500_000))`, i.e. 0.5° (~55 km) cells computed with integer math from the registered `lat_e6/lon_e6`. A cell's weather is fetched at its centre. 1,000 meters in one town = 1 cell = 1 weather series.
- **DECISION: market → region.** New `markets` table: `market_id` (bytes32), `name`, `enabled`, optional bounding box (`min/max lat_e6/lon_e6`, null = global). v1 seeds the one market the contracts know, `keccak256("WATT-mUSDC")`, with a **global** region (all meters). A regional market is just a market with a bounding box; supply for a market is the sum over its meters, each valued with **its own cell's** weather. Markets are managed through the admin API.
- **Weather requests**: one batched Open-Meteo call per poll covers all active cells (comma-separated coordinates), asking for `shortwave_radiation, direct_radiation, cloud_cover, temperature_2m` hourly (today + tomorrow) and `current`. Poll every `WEATHER_POLL_SECONDS` (default **600**, floor 300). That is ~6 requests/hour regardless of meter count, versus Open-Meteo's free limits of 600/min, 5,000/h, 10,000/day. 429 honours `Retry-After`; other failures use exponential backoff with jitter (cap 15 min), 10 s timeout, 2 retries per poll; the last good value is kept and flagged `stale` with its age.
- **Provider interface** `WeatherProvider.fetch(cells, day_range) → CellWeather` (Open-Meteo is the only implementation; the interface is what another source plugs into). Responses are untrusted: shape, length, finiteness and ranges are validated (GHI 0–1500 W/m², temperature −90–70 °C, cloud 0–100 %); a bad payload is treated like a failure.
- Historical days (needed by the demo clock and the backtest) come from the archive endpoint, fetched once per cell per UTC day and cached permanently.
- Hourly values are linearly interpolated to the tick time.

## The model (full derivation and a worked example go in `docs/pricing-model.md`)

All power quantities are in **kW** (average over the pricing horizon); `Decimal` throughout.

1. **Cell temperature / derate**: `T_cell = T_air + 0.03 × G`; `derate = 1 − 0.004 × max(0, T_cell − 25)`; `irr = G / 1000` (G = `shortwave_radiation`, W/m²).
2. **Supply forecast** `S = Σ_meters  capacity_kW × irr × PR × derate`, each meter using its cell's weather; meters = confirmed + active rows in the DB, re-read every tick, so adding a meter changes the next tick's supply.
3. **Demand** `D = D_load + D_bids + D_velocity`:
   `D_load = load_profile(local_solar_hour) × demand_scale × installed_capacity_kW` (configurable 24-point curve; local solar hour from the cell longitude, no tz database);
   `D_bids = open_bid_Wh / 1000 / H` (H = horizon hours, default 1);
   `D_velocity = velocity_weight × recent_fill_Wh / 1000 / window_hours`.
4. **Raw price** `P_raw = P_base × (D / S_eff)^ε`, with `S_eff = max(S, s_floor_frac × installed_capacity_kW)` and the ratio capped at `ratio_cap` so night-time (S = 0) is finite; then clamped to `[P_floor, P_ceiling]`. With no meters (S = D = 0) the price is `P_base`.
5. **EMA** `P_ema = α·P_raw + (1−α)·P_prev`; **rate limit** `|P_new − P_prev| ≤ max_step_pct × P_prev` per tick; final clamp; quantize to an integer.
6. **Realized volatility**: stdev of log returns over the last `vol_window` ticks, published per tick and annualized-free as "bps per √hour".
7. **Circuit breaker** (pure state machine `NORMAL → FROZEN(reason) → RECOVERING → NORMAL`):
   - *stale weather*: any cell used by the market older than `weather_stale_after` (default 30 min) → freeze;
   - *price move*: `> move_pct` within `move_window` (default 15 % in 10 min) → freeze;
   - while frozen: the price is held, `breaker_band_multiplier` widens the published `band_bps` hint, and it only auto-recovers after `recovery_ticks` consecutive healthy ticks (hysteresis) or by an admin reset. Quotes keep being signed (fresh timestamp, held price) so the exchange does not reject them as stale, unless `halt_quotes_on_breaker` is set.

**DECISION: "widen bands".** The on-chain `bandBps` is an admin transaction and the engine has no admin role, so the engine cannot change it. While frozen the engine publishes a widened `band_bps` hint (always capped at the on-chain `bandBps` read from the exchange) for the Phase 4 matcher, and widens its own anomaly thresholds. It never claims to alter the contract.

Proposed default parameters (tunable via admin API, justified in the doc): `P_base 150000` (0.15 mUSDC/kWh), `P_floor 20000`, `P_ceiling 600000`, `ε 0.6`, `PR 0.80`, `α 0.20`, `max_step_pct 1.0 %`/tick, `ratio_cap 10`, `s_floor_frac 0.02`, `demand_scale 0.35`, tick 15 s, `vol_window 40`.

## Clocks: real vs the simulated demo clock

- **DECISION: two separate clocks.** The *market clock* feeds the model inputs (which weather hour, local solar hour for the load curve). The *chain clock* stamps every quote and oracle update. They must differ in demo mode: `PriceOracle`/the exchange reject future or stale timestamps, so quote and oracle timestamps are always real time (anchored to the latest block timestamp, never ahead of it).
- `PRICING_CLOCK_MODE=real` (default) or `follow_readings`: the market clock is the end of the newest interval ingested for simulated meters (`max(interval_start + interval_seconds)`), used only while a reading arrived within `clock_follow_window` real seconds (default 120), otherwise real time. So when `make sim` runs accelerated (one 15-minute interval per 20 s), the engine's weather and load profile sweep through the same simulated day and prices move during a demo; when the simulator stops, the engine returns to real time. No new simulator-to-engine coupling: it follows the same signed readings the pipeline already ingests.
- The tick log/Redis payload carries `market_time`, `quote_timestamp` and `clock_mode`, and demo ticks are labeled `accelerated`.

## Quotes, publishing, persistence, oracle

- **Signed `PriceQuote`** `{marketId, price, timestamp}` in the `WattSwapExchange` domain, signed with the pricer key (`PRICER_PRIVATE_KEY`, already in `.env.example`, distinct from the other role keys). Deterministic signatures (RFC 6979).
- **Redis**: each tick publishes an envelope `{type:"price", channel:"price:{marketId}", seq, ts, data}` on `price:{marketId}` (Phase 5 forwards it unchanged), and stores the latest tick and quote under `price:{marketId}:latest` / `quote:{marketId}:latest`. `seq` is a Redis counter so clients can detect gaps.
- **Postgres**: every tick is persisted to `price_ticks`. Migration `0002` reshapes it (`supply_w`, `demand_w`, `ema_price`, `band_bps`, `breaker_state`, `breaker_reason`, `weather_age_s`, `vol`, `market_time`, `quote_timestamp`, `clock_mode`) and adds `markets` and `pricing_params` (+ an append-only `pricing_param_changes` audit log).
- **Oracle push**: only the primary market is pushed (**DECISION**: `PriceOracle` is single-price by design; making it per-market is a contract change I am not proposing, recorded in ADR-007). Push when the price moved `>= push_threshold_bps` (default 50) since the last push, or a heartbeat interval elapsed (default 120 s, well inside the oracle's 5-minute staleness), never faster than `push_min_interval` (30 s). Timestamps must be strictly increasing and not in the future, so they come from the chain clock; failures retry with backoff like the mint worker and never block ticking.
- **Single writer**: the ticker, poller and pusher run in the API process behind Redis leader locks (same pattern as the mint worker). State (EMA, last price, breaker, history window) is restored from the last persisted tick after a restart.

## Test plan

- **Pure core, hand-computed**: every formula has a worked example computed by hand and asserted exactly (cell temp, derate, supply with two cells, load profile, demand terms, raw price including the `S = 0` and no-meter cases, floor/ceiling clamp, EMA, rate limit). Example: 5 kW, G = 800, T = 30 → T_cell 54 → derate 0.884 → `S = 5 × 0.8 × 0.8 × 0.884 = 2.8288 kW`.
- **Behaviour**: clamp at both ends, EMA convergence, rate limiter never exceeded over thousands of steps, breaker transitions (stale → freeze → hold → hysteresis → recover, move trigger, manual reset, band widening capped at on-chain band), restart continuity.
- **Properties (hypothesis)**: price always in `[floor, ceiling]` and an `int`; step size ≤ limit; deterministic (same inputs → byte-identical tick); more supply never raises the raw price (ε > 0); more demand never lowers it.
- **Weather with respx**: normal data; request shape (batched cells, parameters); timeout; connection error; `429` with and without `Retry-After`; `5xx`; malformed (wrong length, NaN, out-of-range, wrong type, missing keys, empty); partial failure; recovery after failure; **stale data trips the breaker and recovery clears it**; call-count assertions prove the rate budget (one batched request per poll; no per-meter requests; cached archive days are not refetched).
- **DB-driven supply**: registering a meter through the API changes the next tick's supply and lowers the price; deactivating it raises it; two markets with different regions price independently.
- **Units / chain (Anvil)**: (1) the integer price from a tick equals the amount the exchange charges (`cost = fill × price / 1000` check against `MockUSDC` in a real settle); (2) a Python-signed quote's digest equals `exchange.hashQuote(q)` and its recovered signer holds `PRICER_ROLE` on `PriceOracle`; (3) a full `WattSwapExchange.settle()` using the engine's quote succeeds, and fails with `StaleQuote` / `PriceOutsideBand` when it should; (4) the oracle pusher updates `PriceOracle` (price, monotonic timestamp, `isFresh`), honours the threshold/heartbeat rules, and survives a reverted or failed push.
- **Vectors**: Foundry generates additional `PriceQuote` vectors (price `1`, `uint128` max, large timestamp, a second market id); a Python test must reproduce every signature byte-for-byte, and the TS shared tests keep passing.
- **Admin**: auth (401/403), validation errors, audit log rows, change takes effect next tick, defaults/bounds reported.
- **Demo clock**: `follow_readings` with simulated readings moves weather hour and load profile; falls back to real time when readings stop; quote timestamps stay real-time throughout.
- **Backtest**: deterministic output on a fixture, summary statistics match hand-computed values, CLI exit codes.
- **Integration (CI gate)**: Anvil + Postgres + Redis, simulator in demo mode, engine running: prices move across the accelerated day, ticks land in Redis and `price_ticks`, quotes verify on-chain, oracle updates.
- Gates before push: `make lint`, `make test`, contract tests untouched except vectors (coverage stays 100%), CI green.

## Risks

| Risk | Mitigation |
|---|---|
| Open-Meteo slow, rate-limited or wrong | Batched polling, validation, backoff, stale flag, breaker; tests with respx for every failure mode |
| Night-time `S = 0` pins price at the ceiling | `S_eff` floor and `ratio_cap`, plus the rate limiter, make dusk a ramp, not a cliff; shown in the worked example |
| Quote stale or "from the future" on-chain | Timestamps from the chain-anchored clock, never the market/simulated clock; refreshed every tick (15 s vs 5 min staleness) |
| Frozen price while the real market moves | Breaker is visible (state endpoint, tick field, metric), recovers with hysteresis, admin reset, optional `halt_quotes_on_breaker` |
| Single-price oracle vs multiple markets | Quotes are per market; only the primary market goes on-chain; ADR-007 |
| `Decimal` `ln/exp` for the power law | Fixed context precision, deterministic; tests pin outputs; ε of 1 and 0.5 have closed-form checks |
| Two API instances double-quote | Redis leader lock; restart restores state from the last tick |
| Windows/Git Bash friction | Same `make` flow as earlier phases |

## Decisions I'm proposing (override any with your "go")

1. Market → region: `markets` table with an optional bounding box; v1 seeds one **global** market (`WATT-mUSDC`); supply per meter uses its own 0.5° cell's weather.
2. Only the primary market is pushed to the single-price `PriceOracle`; no contract change.
3. **Quote verification is done by `WattSwapExchange`, not `PriceOracle`** (the oracle only stores the price and defines staleness and the signer role). The on-chain test therefore checks the exchange's `hashQuote` digest, the signer's `PRICER_ROLE` on the oracle, and a full `settle()` with the engine's quote.
4. `price_quote` already exists as a Phase 1 vector; I add edge-case PriceQuote vectors instead of duplicating it.
5. "Widen bands" means a published `band_bps` hint capped at the on-chain band; the engine cannot change the on-chain band.
6. Demo: separate market clock (follows ingested readings) and chain clock (all signed/on-chain timestamps).
7. The engine runs inside the API process (leader-locked) rather than a new service.
8. Demand uses fixed-parameter profile + bids + fill velocity as above; bids and fills read as 0 until Phase 4.
9. Parameter defaults above; all admin-tunable.

## Owner changes to the plan (all implemented)

1. **Supply is not generation-only.** `S = w_gen·Gen + w_inv·I` with `w_gen = 1.0`, `w_inv = 0.5`; inventory is open sell volume once the book exists, until then the WATT held by the owners of active meters (read from the chain). A floor `S_min = max(0.1 kW, 10 % of installed)` keeps `D/S` finite. Night with no sun gives an inventory-driven price (146 599 with 24 kWh held; 222 203 with nothing held), never the ceiling.
2. **Limiter and breaker are consistent, and the breaker watches the RAW price.** Max step 0.25 %/tick; the limiter alone moves the applied price at most 10.50 % up / 9.53 % down per 10-minute window, below the 15 % trigger, and `cross_check()` enforces that for every parameter set (and refuses to boot at an inconsistent tick rate). Stale weather (30 min) freezes; a raw move > 15 % in 10 min only widens the `band_bps` hint (capped at the on-chain band) and logs an anomaly event. The state machine and transition table are in `docs/pricing-model.md`.
3. **Full-day trace** (midnight, sunrise, noon, sudden cloud, anomaly clearing, sunset, plus a weather-outage variant) with raw price, EMA, applied price, limiter and breaker at each point, in the doc and in tests; a test fails if the doc table differs from the engine.
4. **Price drivers on every tick**: supply term, demand term, weather inputs per cell, clamps, breaker state, band, and a demand/supply/generation/inventory attribution of the change, stored in `price_ticks.drivers` (JSONB) and sent on the Redis feed and `/price`.
5. **Standalone entry point**: `python -m app.pricing.run` (`make pricing`, compose profile `pricing`), same code and leader lock as the embedded engine.

Previously approved deviations, as built: the exchange (not the oracle) verifies quotes; the single-price `PriceOracle` follows the primary market only (ADR-007); extra `PriceQuote` vectors instead of a duplicate; `band_bps` is a capped hint; two clocks for the demo.

## Findings during the build (all fixed or documented)

- **Demand and generation both scale with installed capacity**, so with no inventory, registering meters raises supply but not the raw price. Kept as the approved model, documented, and added an optional `base_demand_kw` (default 0) so consumer demand that does not scale with PV can be modelled; tests cover both.
- **A start-up race** (the weather poller and the ticker both created the default market) would have crashed an iteration on a fresh database; `ensure_default_market` is now an idempotent upsert with a 12-way concurrency test.
- **A 1 s tick would have broken the limiter/breaker rule**, found when running the engine as a separate process; the service now refuses to boot at such a tick rate.
- **Western longitudes produced a negative local hour** (Decimal `%` keeps the dividend's sign); caught by a hand-computed test and fixed.
- **Cold start**: ticking before the first weather poll froze every restart for the recovery hysteresis; the service now polls once before it starts ticking.

## Known limitations / tech debt

- Demand is a model; bids and fills are 0 until Phase 4. Before the order book exists, "tradeable inventory" is the WATT *held* by active meters' owners, including WATT they may not intend to sell.
- `PriceOracle` holds one price; only the primary market is pushed on-chain.
- The engine cannot change the on-chain band, only publish a capped hint.
- The backtest's inventory is a simple ledger (no order book in a replay) and runs at about 1 000 ticks/second.
- Quote and oracle timestamps assume a chain that produces blocks; on an idle dev chain the wall clock is used.
- The embedded engine runs in the API process; moving it to its own container only needs the `pricing` compose profile and `PRICING_EMBEDDED=false`.
